[ ] PHASE 5 — Progressive disclosure for code AND docs (Goal 4)
--------------------------------------------------------------------------------
Goal: Adopt+adapt codebase-memory's tiered disclosure; apply it to markdown docs too.
Scope:
  - Tier 1 (handles): search results return path/qualified_name + line range + metadata,
    NO bodies by default. Add `detail: ids|default` (ids = bare handles for wide sweeps).
    Keep snippet available under `detail=default` but ensure body text is not dumped.
  - Tier 2 (fetch): add a unified fetch tool (e.g. `get_snippet` / `read_chunk`) that returns:
      * for code: symbol source by stored start/end line, capped (e.g. 500 lines), with
        optional `include_neighbors` (caller/callee handles);
      * for docs: the specific matched chunk (by path + chunk_index) or heading section,
        capped, with optional neighbor chunks (prev/next heading section).
  - Tier 3 (full file): read_note (docs) + a read_code_file (or generalize read_note) for
    whole-file reads; keep as the explicit last resort.
  - Encode the ordering in tool descriptions ("search for handles first; fetch source only
    for what you need; read the whole file only if required").
Acceptance:
  - Search returns handles without bodies at `detail=ids`; default keeps a short snippet only.
  - A single fetch call retrieves exactly one code symbol OR one doc chunk/section, bounded.
  - Neighbor expansion works for both code (callers/callees) and docs (adjacent sections).
Verify: just clippy && just check ; targeted test for handle->fetch->full flow on a doc and a symbol.
Commit: feat(phase5): tiered progressive disclosure for code and docs
