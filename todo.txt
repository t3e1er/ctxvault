PHASE 2: GENERIC-NORMALIZED SCOPE PATH RESOLUTION FOR CODE SYMBOLS
--------------------------------------------------------------------------------
Goal: Enable Tier-2 `get_snippet(qualified_name = "...")` to resolve qualified names
with omitted generic type/lifetime parameters (e.g. `Type > method` matching
`Type<'tcx, T> > method`) instead of returning 404 Not Found.

[x] Task 2.1: Add generic-normalization helper in `ctxvault-core`
    - Implement a pure function `normalize_scope_path(scope: &str) -> String` that
      strips balanced angle brackets `<...>` and lifetime annotations while preserving
      scope hierarchy separators (` > `).
    - Example: `EarlyBinder<'tcx, T> > instantiate` -> `EarlyBinder > instantiate`.
    - Add unit tests covering nested generics (e.g. `Foo<Bar<T>> > baz`, `Closure<'a>`).

[x] Task 2.2: Add normalized query fallback to `MetadataCatalog` / SQLite catalog
    - In `crates/ctxvault-core/src/persistence/mod.rs`:
      - When `find_symbols_by_qualified_name(qualified_name)` yields 0 exact matches:
        - Query SQLite with a component-matching pattern: split `qualified_name` by ` > `,
          and match candidate symbols where the symbol `name` matches the leaf and
          `scope_path` matches the enclosing scope prefix ignoring generics.
        - Alternatively query via SQL `LIKE` wildcard: `replace(query, ' > ', '% > %')`.
        - If multiple matches result, return all candidates for disambiguation.

[x] Task 2.3: Wire fallback into `fetch_code_symbol` in `crates/ctxvault-mcp/src/tools/mod.rs`
    - Ensure `fetch_code_symbol` invokes the normalized fallback when exact lookup fails.
    - If disambiguation is needed, return the candidate list with exact `scope_path`s.

[x] Task 2.4: Unit tests for generic scope path resolution
    - Test that `EarlyBinder > instantiate` resolves to `EarlyBinder<'tcx, T> > instantiate`.
    - Test that nonexistent symbols still return clean `404 Not Found`.
    - Test that ambiguous methods return disambiguation candidates.

[x] Task 2.5: Verification & Phase 2 Commit
